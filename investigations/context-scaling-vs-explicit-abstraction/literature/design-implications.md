# Literature-Derived Design Implications

These are preregistration requirements derived from the reviewed adjacent literature. They do not execute or amend the investigation.

1. **Measure effective availability, not nominal capacity.** Long-context work shows that information placement and use can matter. Freeze the source-unit ordering, `N`/`M` selections, unitization, and accounting; report which units are available in each condition (S1–S3).
2. **Keep retrieval and memory out of the factorial treatment unless explicitly crossed.** Retrieval and managed memory introduce selection, read/write, and update policies. Hold them absent or identically fixed across conditions, and record this choice (S4–S6).
3. **Do not equate a shorter object with abstraction.** If any compression is used to meet a budget, record the method and treat it as a potential confound unless it is identical across conditions. Evaluate the abstraction artifact’s generalization, declared scope, limitations, and provenance separately (S7–S8).
4. **Define transfer distance before data collection.** Transfer literature indicates that representation reuse depends on task relatedness. Freeze the target-task difference dimensions and report results by task family/distance where the design supports it (S10–S11).
5. **Separate artifact effects from feedback and iteration.** Reasoning traces, reflection, and skill libraries can bundle an artifact with tools, evaluator feedback, retry loops, retrieval, or environment state. The planned comparison must hold those mechanisms fixed or exclude them (S12–S15).
6. **Audit the target package.** For every target evaluation, preserve the complete package, order, budget, retained-object inventory, and deterministic reductions. This is necessary to distinguish context availability from a reusable representation.
7. **Use neutral outcome language.** The literature motivates the test but supplies no result for this design. Preserve support, violation, indeterminate, and methodology-failure outcomes; do not use review findings as empirical support.

## Pre-Registration Gate

Before preregistration, incorporate these requirements into a versioned registration without changing the candidate hypothesis to seek novelty. If any requirement cannot be specified or enforced, stop rather than interpret a confounded comparison.
